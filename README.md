# ProjectPilot

基于 [nanobot](https://github.com/HKUDS/nanobot) 扩展的本地 AI 项目分析工作台。可以导入公开 GitHub 仓库，让模型读取源码并生成分析结果与报告，也可以根据本地文档提问，在不同会话间使用已保存的项目决定。

当前按单机单用户运行。离线演示无需模型密钥；真实分析需要自行配置兼容的模型服务。

工作台按“项目 → 任务”组织对话。创建项目与任务后，可以切换任务、恢复草稿，管理项目资料和记忆。任务模式、记忆开关和长对话策略在创建后固定，运行环境在首次有效发送后固定。更新后请重启工作台服务。报告目前可在运行详情查看和导出，正式报告管理与旧数据迁入尚未实现。

## 功能

| 功能 | 使用方式 |
|---|---|
| 仓库分析 | 导入公开 GitHub 默认分支快照，或指定本地目录，让模型搜索和读取源码、生成报告 |
| 知识问答 | 选择 TXT、Markdown 或带文字层的 PDF，根据检索片段回答并引用来源 |
| 项目记忆 | 保存项目模型决定和回答语言偏好，支持跨会话召回、替代与撤回 |
| 上下文管理 | 使用完整历史、近期窗口或摘要策略，控制请求预算并保留原始会话 |
| 运行记录 | 查看工具过程，停止任务，下载报告和结果 ZIP |
| 评测中心 | 使用内置题目比较配置，查看失败和待复核项 |

## 安装与启动

建议使用 Python 3.12。目前已验证 Windows / Python 3.12 的源码安装与离线流程；其他平台和容器部署仍需实际验收。

先获取源码：

```bash
git clone https://github.com/Jackylov377/ProjectPilot.git
cd ProjectPilot
```

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe scripts/prepare_tokenizer.py
.\.venv\Scripts\python.exe -m app.doctor
.\.venv\Scripts\python.exe -m app.api
```

### macOS / Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python scripts/prepare_tokenizer.py
.venv/bin/python -m app.doctor
.venv/bin/python -m app.api
```

首次安装需要联网下载依赖和固定的分词资源。打开 [本地工作台](http://127.0.0.1:8765)，保留启动终端，按 `Ctrl+C` 停止服务。

当前网页可查看旧历史和运行；旧发送入口会明确提示改用任务接口。新任务的本地演示会执行工具并保存状态，但回答来自预设逻辑，只用于验证流程。

## 接入真实模型

将 [.env.example](.env.example) 复制为本地 `.env`，填写服务地址、可用模型标识和自己的密钥。已有配置时直接编辑，不要覆盖。

| 配置项 | 内容 |
|---|---|
| `PROJECTPILOT_API_BASE` | 模型服务的兼容 API 地址 |
| `PROJECTPILOT_MODEL` | 账号实际可用的模型标识 |
| `PROJECTPILOT_API_KEY` | 本地保存的服务密钥 |

停止原服务，再运行：

```powershell
.\.venv\Scripts\python.exe -m app.doctor --live
.\.venv\Scripts\python.exe -m app.api --allow-live
```

macOS / Linux 将 Python 路径换成 `.venv/bin/python`。doctor 只检查配置，不请求模型。新任务首次发送前需要主动选择“本地演示”或“真实模型”，不预选。分析时，问题及被读取的源码或资料片段会发送到配置的服务，并可能产生费用。

## 使用核心功能

1. 点击“新建项目”，选择注册的本地仓库、公开 GitHub 来源或纯资料项目。同仓库优先打开已有项目，也可明确新建独立项目。
2. 在项目下“新建任务”，填写名称，并主动选择任务模式、项目记忆启用／关闭、长对话策略。创建后这三项不可修改；任务名和项目名可重命名。
3. 首次发送前选择运行环境；接收后固定。顶部摘要可查看配置，资料设置按需展开。任务输入草稿分别保存，刷新后恢复；运行期间可查看其他任务、写草稿和整理资料，下一次发送等待当前运行结束。

侧边栏“改造前数据”单独访问旧对话、旧共享资料及旧范围记忆。旧对话只读，不自动迁入新项目；新项目内部的历史和资料旧版本始终留在所属项目。

全新工作空间的侧边栏只保留“新建项目”入口，不预置项目或任务；创建第一个项目后才展示项目列表和功能导航。已创建项目刷新后正常恢复。需要从空白工作空间自行测试真实模型时，可使用独立数据目录：

```powershell
.\.venv\Scripts\python.exe -m app.api --workspace . --data-dir runs/live-workspace --port 8874 --allow-live
```

在 [真实模型工作台](http://127.0.0.1:8874) 新建项目和任务，在页面右上角选择“真实模型”后首次发送。此目录与默认旧数据、临时演示数据分开，使用已有 `.env` 模型配置。

**分析仓库：** 创建仓库项目时填写公开 GitHub 仓库链接，获取源码后再创建仓库分析报告任务。页面不提供已导入快照选择。获取源码不调用模型，也不执行仓库代码。“项目与来源”可重新获取当前仓库并点击应用，仅影响当前项目后续运行。生成报告可在运行详情查看、导出；运行产物不等于用户正式保存的报告。

当前支持公开仓库的默认分支，可接受 `.git` 后缀。下载上限 20 MB，解压上限 60 MB，最多 8000 个条目；私有认证和指定分支尚未接入。

也可以启动时指定本地仓库：

```powershell
.\.venv\Scripts\python.exe -m app.api --allow-live --workspace C:\path\to\repository --data-dir runs/my-workbench --port 8767
```

此时打开 [8767 端口工作台](http://127.0.0.1:8767)。同一数据目录只运行一个服务。

**知识资料：** 在“项目资料”上传、预览及显式修订 TXT、Markdown 或文本 PDF，单文件最多 4 MiB。在知识任务中选择最多 20 份资料，点击“应用到任务”后生效；未选资料或修改尚未应用时不能发送。修订保留旧版本，旧引用可以核对原件。旧共享资料不自动进入项目；扫描 PDF 的 OCR 尚未实现。

知识问答可选择 BM25、语义检索、混合检索和混合检索加重排。BM25 默认开启且检索本身在本地完成。其他方式仅在真实模型模式下可选，需要按 `.env.example` 配置独立的 `PROJECTPILOT_EMBEDDING_*`；重排额外需要 `PROJECTPILOT_RERANK_*`。Embedding 接口兼容 OpenAI 格式，重排接口兼容 DashScope 格式。高级检索会将选中文档的片段及问题发送至这些服务，配置后重启工作台。

命令行示例（将路径和文件名替换为自己的资料）：

```powershell
.\.venv\Scripts\python.exe -m app.cli --engine knowledge --mode live --workspace C:\path\to\docs --knowledge-files guide.md --retriever hybrid --prompt "资料中的操作流程是什么？"
```

语义检索采用余弦排序；混合检索以 RRF 合并关键词与语义排名，重排最多处理 10 个候选。未变化文档的向量缓存在当前工作区状态目录的 `rag-cache/` 下，跨回合复用；文档版本、片段范围、服务地址、模型或维度改变后重新计算。查询向量每次生成。缓存只保存向量，不保存原文或密钥；它仍属于本地资料衍生数据，旧缓存暂不自动清理。删除或取消选择的文档不会再进入检索。

这一版高级检索限制为最多 256 个片段，向量准备及查询合计最多等待 15 秒，重排最多等待 6 秒；超限或语义服务失败时回退 BM25，重排失败时保留混合检索，本回合不重复尝试已失败的阶段。工作台通知、运行详情及 Trace 会记录回退。Trace 还记录实际检索方式、耗时、缓存命中以及服务报告的用量和请求尝试数（回合累计）；缺失用量不能当作零费用。这些机制不代表已验证真实问答质量提升。

知识问答中，连续两次检索没有返回本回合的新片段，就停止检索并依据已有证据回答；证据不足则明确无法确认。新片段会重置计数，空结果计入，工具报错不计入。首次命中后再连续两次重复，通常共检索 3 次；连续空结果则共检索 2 次。停止检索不代表已经证明资料中没有答案。

**项目记忆：** 同项目、同环境下启用记忆的任务可以跨两种模式共享受支持的决定与偏好；关闭任务不读、不抽取、不写入。项目记忆页可选择查看环境、查看来源与历史、撤回记录；筛选不改变任务环境。旧记忆通过“改造前数据”访问，不自动迁入。自动记忆主要支持模型选择与回答语言；撤回不恢复旧值，同项目运行期间暂停人工修改。

**使用评测中心：** 评测环境独立选择，不改变任务环境。先选择少量内置题目、一个配置、重复一次。离线结果用于观察流程，执行结束与评测通过分别判断，内容质量仍需要人工复核。

## 数据与限制

运行数据默认保存在 `runs/web/`，分词缓存位于 `.cache/tiktoken/`。关闭网页不会自动取消任务，需要在运行记录中停止。报告及最终回答以保存的结果为准，生成预览可能被后续纠正。

运行失败时，在“运行记录”打开该任务，查看原因与处理建议。按页面显示的任务编号，可以在数据目录的 `jobs/<任务编号>/diagnostic.json` 查看脱敏诊断；该文件只保存在本地。损坏的历史任务会单独标为失败，原始文件保留，其他任务可继续使用。修改 `.env` 后需要重启服务。

模型可能遗漏逻辑或作出过强推断；引用位置正确不代表结论正确。知识问答默认使用 BM25，尚未实现通用的无答案判断。自动记忆和摘要可能超时。当前没有多用户认证，按本地工作台使用。

## 工作空间存储与只读清点

项目与任务保存在独立的工作空间存储中，包含固定配置、运行环境和资料版本。旧对话和旧记忆保留在原有范围内，不会自动归入新项目。维护时可以先只读清点现有数据，再决定如何处理。

对默认应用数据执行只读清点：

```powershell
.\.venv\Scripts\python.exe scripts/inventory_workspace.py --data-root runs/web --snapshot
```

工具读取经文件指纹核对的临时副本，输出 Markdown 摘要及 JSON 明细，不启动工作台、不调用模型、不迁移记录。输出位置会在完成后打印；有活动运行或数据变化时不声称取得完整可靠的清单。其他应用数据目录须用 `--data-root` 显式指定。

## 仓库内容与许可证

`app/` 包含后端与网页资源，`examples/demo_project/` 提供默认启动示例，`evals/datasets/agent_dev/tasks_v2.json` 为网页评测中心提供题目。`scripts/prepare_tokenizer.py` 用于准备分词资源。

网页代码从 `app/api/static/app.js` 开始阅读，其中负责启动、导航和事件绑定；`app/api/static/js/` 按页面及任务职责组织具体逻辑。模块由浏览器直接加载，无需额外的前端构建步骤。

ProjectPilot 复用 nanobot 的 Agent 循环、Provider 接口、工具注册与基础 Session，在此基础上实现应用工具、检索、记忆策略和工作台。新增代码采用 [MIT](LICENSE) 许可证，上游及依赖保留各自许可证，详见[第三方说明](THIRD_PARTY_NOTICES.md)。
